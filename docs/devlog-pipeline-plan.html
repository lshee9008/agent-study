기획서 · v2 (구축 완료본)

Hermes 개발일지 자동 발행 파이프라인

작성 승코2026-10-24상태 첫 발행 성공, 주간 자동 실행 등록

일주일에 한 번, GitHub 커밋과 Notion 기록을 모아 레포별 개발일지를 쓰고 Velog에 비공개로 올려두는 셀프호스팅 에이전트다. 사람은 비공개 글을 읽고 공개 버튼만 누른다. 상시 서버 없이 맥 한 대와 무료 API로 돌아간다.

01개요

배경. 프로젝트를 여러 개 동시에 하면 작업 기록은 커밋과 회의록에 쌓이지만, 그걸 블로그 글로 옮기는 일은 계속 밀린다. 기록은 있는데 정리할 시간이 없다.

목표.

  • 레포별 주간 개발일지 초안을 자동으로 쓴다
  • 사람은 비공개 글을 검토하고 공개만 결정한다
  • 상시 서버 없이 내 맥 한 대로 운영한다

핵심 원칙. 추가 비용 0원, 사람이 검수하기 전에는 절대 공개되지 않는 비공개 발행, 에이전트에게는 읽기와 비공개 쓰기 권한만.

v1 기획서와 달라진 점. 처음엔 맥에서 도는 로컬 모델(Ollama, qwen3:8b)로 계획했지만, 16GB 맥에서 64K 컨텍스트를 감당하기 빠듯하고 모델 다운로드도 느려 NVIDIA API(build.nvidia.com)의 오픈소스 모델로 바꿨다. 비용은 여전히 0원이지만, 커밋·노션 내용이 NVIDIA 서버로 전송된다는 점이 달라졌다. 민감한 레포는 대상에서 빼야 한다.

02범위

이번 버전은 "주 1회 비공개 초안 자동 발행"까지만 한다. 공개 여부 판단과 글 다듬기는 사람이 맡는다.

구분내용
포함GitHub 커밋·PR·이슈 읽기, Notion 페이지 읽기, 레포별 개발일지 초안 작성, Velog 비공개 발행, 맥이 켜져 있을 때만 주기 실행, 시작·완료·실패 알림
제외공개 발행, 기존 글 수정·삭제, 상시 서버, 클라우드 배포, 이미지·썸네일 생성, 유료 모델

03시스템 구조

실행 주체는 전부 내 맥 안에 있다. 외부와는 읽기 2곳(GitHub, Notion), 쓰기 1곳(Velog 비공개), 모델 호출 1곳(NVIDIA)만 연결된다.

04실행 흐름

한 번의 실행은 7단계로 끝난다. 조건이 맞지 않으면 2단계에서 아무것도 하지 않고 종료한다.

  1. 깨우기. 맥 로그인 시, 그리고 켜져 있는 동안 1시간마다 launchd가 run-if-due.sh를 호출한다.
  2. 조건 확인. 마지막 성공 후 7일이 지났는지, 충전기가 연결돼 있는지 본다. 하나라도 아니면 조용히 종료한다.
  3. 준비. NVIDIA API에 닿는지 확인하고, Docker가 꺼져 있으면 켠다. 중복 실행은 잠금 폴더로 막는다.
  4. 실행. docker compose run --rm으로 Hermes 컨테이너를 일회성으로 띄운다. 도중에 잠들지 않게 caffeinate로 감싸고, 도구 호출 80회·30분 상한을 건다.
  5. 수집. Hermes가 MCP로 GitHub 커밋·PR과 Notion 페이지를 읽고 원문을 _raw-날짜.md로 남긴다.
  6. 작성·발행. velog-devlog 스킬 절차대로 레포별 초안을 drafts/에 쓰고 Velog에 비공개로 올린 뒤, 다시 읽어 비공개 여부를 검증한다.
  7. 정리. 성공 시각을 기록하고 맥 알림을 띄운다. 실패하면 기록을 남기지 않아서 1시간 뒤 자동 재시도한다. 맥이 며칠 꺼져 있었다면 다음에 켰을 때 밀린 한 번을 실행한다.

08구축하며 부딪힌 문제와 해결

따라 만드는 사람이 같은 데서 막히지 않도록 실제로 겪은 순서대로 적는다.

Hermes 실행이 "Gateway inaccessible: gateway.sock has mode 0755"로 막힘 Hermes는 실행 때마다 내부 게이트웨이를 띄우고 소켓으로 접속한다. 데이터 폴더를 맥 폴더에 바인드하면 소켓 권한이 0755로 보여 보안 검사에 걸린다. 데이터 폴더(/opt/data)는 Docker 볼륨으로 옮기고, 설정 파일 두 개와 스킬만 맥에서 연결해 해결했다.
초안 저장이 "outside HERMES_WRITE_SAFE_ROOT"로 거부됨 공식 이미지는 /opt/data 밖 쓰기를 막는다. HERMES_WRITE_SAFE_ROOT=/opt/data:/opt/workspace/drafts로 초안 폴더만 열었다. (첫 실행 때 에이전트가 셸 복사로 우회해 저장은 됐지만, 우회가 필요 없게 고쳤다.)
스킬 폴더를 /opt/data/skills 안에 겹쳐 연결하자 기본 스킬 복사가 권한 오류 Docker가 상위 폴더를 root 소유로 만들어서 생긴 문제. 프로젝트 skills/를 /opt/skills에 읽기 전용으로 연결하고 skills.external_dirs에 등록했다.
docker compose run hermes mcp list가 엉뚱한 프로그램을 실행 컨테이너 진입 스크립트는 첫 단어가 실행 파일이면 그걸 바로 실행한다. mcp라는 별도 CLI가 있어서 겹쳤다. hermes mcp list처럼 앞에 hermes를 붙인다.
기본 후보 모델 kimi-k2.6이 404 모델 목록에 있어도 계정에 따라 호출이 안 된다. 후보들을 툴 호출 요청으로 직접 테스트해서 고르는 과정을 넣었다(05 참고).
토큰 붙여넣기가 엉뚱한 칸에 들어감 한 줄씩 묻는 입력 방식에 여러 줄을 붙여넣으면 값이 섞인다. set-tokens.sh는 아무 형식으로 한꺼번에 붙여넣으면 접두어(nvapi-, github_pat_, ntn_)와 Velog JWT의 sub 값으로 종류를 구분해 저장한다. 입력은 화면에 보이지 않는다.

./scripts/install-launchagent.sh      # 해제: ./scripts/uninstall-launchagent.sh

12리스크와 대응
